## DSH task routing

Use the installed `deepseek-worker` skill and `delegate_to_deepseek` for clear, low-risk, verifiable simple code (including BFS examples and short scripts), localized fixes with a known cause, independent tests, routine documentation, formatting, and mechanical data processing. Delegate before implementation, even for small tasks. Codex defines scope and acceptance, then reviews the final answer, actual artifacts, and relevant checks. Do not implement first and ask DSH to duplicate it.

Codex directly handles creative discussion, brainstorming, research direction, papers and important writing, complex architecture or coupled implementation, unknown-root-cause debugging, security/authentication/payments/migrations, production-critical work, final decisions, review, and publishing. For mixed tasks, Codex decides first and delegates only independent mechanical subtasks. This DSH rule governs eligible routine tasks even when a general model-routing rule names another worker.

Respect explicit user choices and higher-priority instructions. Use the authorized absolute project_root, a supported explicit thinking_effort, minimal permissions, and one workspace writer. Never send secrets. If the tool or authorization is unavailable, explain briefly and handle permitted work directly. After one corrective continuation still fails, Codex takes over.

Before the first delegation, obtain get_dsh_monitor and open its URL in the Codex browser sidebar when supported; otherwise provide the link and continue. The page is for the user: do not fetch, screenshot, read, or poll it. Read final deliverables and necessary verification evidence; inspect minimal diagnostics only on failure. Do not read raw worker sessions or hidden thinking.
