## Codex and DSH task routing

Codex owns research direction, creative/aesthetic choices, important writing, architecture, high-risk work, integration, acceptance and publishing. Keep instant answers and obvious edits direct. Before substantial mixed implementation, identify a cohesive engineering deliverable. A complex parent does not make every part Codex-only. Prefer DSH implementation with independent Codex acceptance over advisory-only delegation when suitable implementation exists.

Use deepseek-worker. Give DSH settled inputs, exact output interfaces, allowed files, local decisions, examples, resource limits, acceptance and a concise receipt. Delegate a module with its coupled helpers/tests, not every function or the whole research project. Codex resolves scientific/product decisions. After decisions are fixed, delegate suitable runners, statistics and rendering code too; keep interpretation and independent acceptance. Do not duplicate implementation.

Run up to two independent DSH sessions concurrently when supported. Writers use isolated project copies with distinct authorized project_root values, frozen inputs and separate progress cards. Prefer delegate_parallel_to_deepseek for two independent tasks, or concurrent single-task calls when supported. Overlapping write domains and simultaneous resumes of one session are prohibited. The bridge limit is per server, not a cross-process lock. Inspect every outcome and integrate accepted files after workers finish.

Resume corrections with the returned session_id and same root/cwd. After one failed corrective continuation, Codex takes over; do not reset retries with a new session. Review files and run focused independent checks. Keep acceptance fixed, reuse valid evidence and check an independent interface/exclusion case; worker tests alone are insufficient. Use explicit supported thinking_effort and minimal permissions. DSH uses the configured model API; honor user permissions and network limits. Never send secrets or read progress cards, read_dsh_progress, raw logs or hidden reasoning. Never automatically open a sidebar/browser.
